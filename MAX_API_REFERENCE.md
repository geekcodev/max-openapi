# MAX Messenger API — полный справочник

**Base URL:** `https://platform-api2.max.ru`

**Аутентификация:** заголовок `Authorization: <access_token>` (передача токена через query-параметры больше не
поддерживается)

**Важно:** Используйте домен `platform-api2.max.ru` вместо `platform-api.max.ru`. Добавьте сертификат Минцифры в список
доверенных.

**Лимиты запросов:** 30 RPS на `platform-api2.max.ru`. Максимум 2 сообщения/редактирования/удаления/ответа в секунду на
диалог/чат/канал.

**Последнее обновление:** 2026-09-27 (сверка с `dev.max.ru/docs-api/changelog-api` и официальной машинной спекой
`github.com/max-messenger/api-schema` v0.0.33)

## 1. GET /me

**Информация о боте.** Возвращает `BotInfo` (наследует `UserWithPhoto`) с id бота, именем, username, last_activity_time,
описанием, аватаром и командами.

**Аутентификация:** `access_token` (apiKey)

**Ответ:**

| Поле                 | Тип                            | Описание                              |
|----------------------|--------------------------------|---------------------------------------|
| `user_id`            | integer `<int64>`              | ID пользователя/бота                  |
| `first_name`         | string                         | Отображаемое имя                      |
| `last_name`          | string Nullable optional       | Фамилия (не возвращается для ботов)   |
| `username`           | string Nullable                | Имя пользователя/никнейм              |
| `is_bot`             | boolean                        | `true`, если бот                      |
| `last_activity_time` | integer `<int64>` Nullable     | Время последней активности (Unix, мс) |
| `name`               | string Nullable                | **Устарело**                          |
| `description`        | string Nullable optional       | До 16000 символов                     |
| `avatar_url`         | string optional                | URL миниатюры аватара                 |
| `full_avatar_url`    | string optional                | URL полного аватара                   |
| `commands`           | BotCommand[] Nullable optional | До 32 команд                          |

## 2. PATCH /me/commands

**Редактирование команд бота.** Добавляет, редактирует или удаляет команды. Передайте пустой массив `[]`, чтобы удалить
все команды.

**Аутентификация:** `access_token` (apiKey)

**Тело запроса:**

| Поле       | Тип                   | Обязательное | Описание     |
|------------|-----------------------|--------------|--------------|
| `commands` | BotCommand[] optional | Нет          | До 32 команд |

**Объект BotCommand:**

| Поле          | Тип                | Обязательное | Описание                       |
|---------------|--------------------|--------------|--------------------------------|
| `name`        | string 1–64        | **Да**       | Имя команды без `/`            |
| `description` | string 1–128 Null. | Нет          | Описание команды (опционально) |

> Обязателен только `name` — подтверждено `schema.yaml`, схема `BotCommand` (проверено 2026-09-27). Раньше спека
> требовала оба поля.

**Ответ:**

| Поле       | Тип                   | Описание     |
|------------|-----------------------|--------------|
| `commands` | BotCommand[] optional | До 32 команд |

| Поле                 | Тип                                    | Описание                                                     |
|----------------------|----------------------------------------|--------------------------------------------------------------|
| `chat_id`            | integer `<int64>`                      | ID чата/канала                                               |
| `type`               | enum `ChatType`                        | `"chat"`, `"channel"` или `"dialog"`                         |
| `status`             | enum `ChatStatus`                      | `"active"`, `"removed"`, `"left"`, `"closed"`, `"suspended"` |
| `title`              | string Nullable                        | Название чата/канала (null для диалогов)                     |
| `icon`               | object Image Nullable                  | Иконка чата                                                  |
| `last_event_time`    | integer `<int64>`                      | Время последнего события                                     |
| `participants_count` | integer `<int32>`                      | Количество участников (для диалогов всегда 2)                |
| `owner_id`           | integer `<int64>` Nullable optional    | ID владельца                                                 |
| `participants`       | object Nullable optional               | Участники с временем активности                              |
| `is_public`          | boolean                                | Публичный доступ (для диалогов всегда false)                 |
| `link`               | string Nullable optional               | Ссылка на чат                                                |
| `description`        | string Nullable                        | Описание                                                     |
| `dialog_with_user`   | object UserWithPhoto Nullable optional | Собеседник в диалоге (только для типа dialog)                |
| `messages_count`     | integer Nullable optional              | Количество сообщений                                         |
| `pinned_message`     | object Message Nullable optional       | Закреплённое сообщение (только при запросе конкретного чата) |

| Поле          | Тип                                                    | Обязательное | Описание                                                                        |
|---------------|--------------------------------------------------------|--------------|---------------------------------------------------------------------------------|
| `icon`        | object PhotoAttachmentRequestPayload Nullable optional | Нет          | Запрос прикрепления изображения (поля взаимоисключающие)                        |
| `title`       | string Nullable optional                               | Нет          | 1–200 символов                                                                  |

**Ответ:** (объект Chat — как в GET /chats/{chatId})

## 12. POST /chats/{chatId}/members/admins

**Назначить администратора (ов).** Выдаёт права администратора пользователям/ботам, которые являются участниками чата
или подписчиками канала. Бот должен быть администратором с правом `add_admins`.

**Аутентификация:** `access_token` (apiKey)

**Параметры пути:**

| Параметр | Тип                                   | Описание       |
|----------|---------------------------------------|----------------|
| `chatId` | integer `<int64>` (pattern: `\-?\d+`) | ID чата/канала |

**Тело запроса:**

| Поле     | Тип                                 | Обязательное | Описание                                                   |
|----------|-------------------------------------|--------------|------------------------------------------------------------|
| `admins` | ChatAdmin[]                         | Да           | Список пользователей/ботов для назначения администраторами |
| `marker` | integer `<int64>` Nullable optional | Нет          | Указатель следующей страницы                               |

Каждый `ChatAdmin` содержит:

- `user_id` — ID пользователя/бота
- `permissions` — массив строк `ChatAdminPermission`
- `alias` — строковое описание роли

**Повторный вызов метода с тем же пользователем заменяет его права (семантика PUT).**

**Ответ:**

| Поле      | Тип             | Описание                     |
|-----------|-----------------|------------------------------|
| `success` | boolean         | `true` при успехе            |
| `message` | string optional | Пояснение ошибки при неудаче |

## 18. POST /subscriptions

**Создание webhook-подписки** (основной механизм доставки событий для production). Long Polling отключается, когда
подписка активна.

**Аутентификация:** `access_token` (apiKey)

### Модель доставки событий:

1. Событие возникает → POST на webhook-эндпоинт с объектом `Update`
2. TLS-валидация эндпоинта
3. Если задан `secret`, проверяется заголовок `X-Max-Bot-Api-Secret`
4. Эндпоинт должен вернуть HTTP 200 в течение 30 секунд
5. Экспоненциальные повторные попытки: 60 с → 150 с → 375 с → ... (10 попыток за ~8 часов)
6. Если успеха нет в течение 8 часов, бот автоматически отписывается

### Требования к webhook-эндпоинту:

- Только HTTPS на порту 443
- TLS-сертификат от доверенного CA или сертификат Минцифры (без самоподписных)
- Домен должен совпадать с CN или SAN
- Обязательна полная цепочка сертификатов

**Тело запроса:**

| Поле           | Тип               | Обязательное | Описание                                                                            |
|----------------|-------------------|--------------|-------------------------------------------------------------------------------------|
| `url`          | string            | Да           | URL HTTPS-эндпоинта (должен начинаться с `https://`)                                |
| `update_types` | string[] optional | Нет          | Например, `["message_created", "bot_started"]` (полный список см. в объекте Update) |
| `secret`       | string optional   | Нет          | 5–256 символов, `[a-zA-Z0-9_-]` — передаётся в заголовке `X-Max-Bot-Api-Secret`     |

**Ответ:**

| Поле      | Тип             | Описание                     |
|-----------|-----------------|------------------------------|
| `success` | boolean         | `true` при успехе            |
| `message` | string optional | Пояснение ошибки при неудаче |

## 21. POST /uploads

**Загрузка медиафайлов.** Возвращает URL для загрузки и токен для прикрепления к сообщениям.

### Поддерживаемые типы и лимиты:

| Тип     | Форматы                              | Максимальный размер                             |
|---------|--------------------------------------|-------------------------------------------------|
| `image` | JPG, JPEG, PNG, GIF, TIFF, BMP, HEIC | 50 МБ или 7680×7680 px (оба лимита обязательны) |
| `video` | MP4, MOV, MKV, WEBM                  | 250 МБ                                          |
| `audio` | MP3, WAV, M4A и другие               | 256 МБ или 60 минут (оба лимита обязательны)    |
| `file`  | TXT, DOC, PDF и другие               | 4 ГБ                                            |

### Домены загрузки:

- `file` → `https://fu.oneme.ru`

1. **Resumable-загрузка** (не multipart/form-data) — можно возобновить при сбое
2. **Multipart-загрузка** (`Content-Type: multipart/form-data`) — проще, но при сбое нужно начинать заново

**Query-параметры:**

| Параметр | Тип               | Обязательное | Описание                                  |
|----------|-------------------|--------------|-------------------------------------------|

| Поле    | Тип             | Обязательное | Описание                                                   |

| `url`   | string          | **Да**       | URL для загрузки (без срока действия)                      |
| `token` | string Nullable | Нет          | Токен для `attachments.payload.token` в POST/PUT /messages |

> Обязательность `url` подтверждена официальной `schema.yaml` (схема `UploadEndpoint`, `required: [url]`); `token`
> возвращается для `video`/`audio` и объявлен nullable (уточнено 2026-10-20).

**Примечание по обработке:** после загрузки подождите перед отправкой сообщения, чтобы избежать ошибки

### Объект Update

Описывает события в чатах/каналах. Доставляется через Webhook (POST /subscriptions) или Long Polling (GET /updates).

**Типы событий:**

| Тип события                     | Описание                                                             |
|---------------------------------|----------------------------------------------------------------------|
| `bot_added`                     | Бот добавлен в чат/канал                                             |
| `bot_started`                   | Пользователь начал/возобновил диалог с ботом                         |
| `bot_stopped`                   | Пользователь остановил/удалил бота (с `dialog_removed` при удалении) |
| `bot_removed`                   | Бот удалён из чата/канала                                            |
| `chat_title_changed`            | Изменено название чата/канала                                        |
| `dialog_cleared`                | Пользователь очистил историю диалога                                 |
| `dialog_muted`                  | Пользователь отключил уведомления диалога                            |
| `dialog_unmuted`                | Пользователь включил уведомления диалога                             |
| `dialog_removed`                | Пользователь удалил диалог (также вызывает `bot_stopped`)            |
| `message_callback`              | Пользователь нажал кнопку                                            |
| `message_created`               | Новое сообщение или пост в канале                                    |
| `message_edited`                | Сообщение отредактировано                                            |
| `message_removed`               | Сообщение удалено                                                    |
| `user_added`                    | Новый пользователь вступил в чат/канал                               |
| `user_removed`                  | Пользователь удалён из/покинул чат/канал                             |
| `comment_created`               | Создан комментарий к посту в канале                                  |
| `comment_edited`                | Комментарий отредактирован                                           |
| `comment_removed`               | Комментарий удалён                                                   |
| `bot_admin_permissions_changed` | Изменились права администратора бота                                 |

> Три события комментариев бот получает, **только если он администратор канала** с правом `read_all_messages`.
>
> Событие `bot_admin_permissions_changed` доставляется **только при подписке через вебхук** (в Long Polling
> недоступно). С октября 2026 оно перечислено на странице объекта `Update` в текстовой доке, состав полей —
> по официальной `schema.yaml` (схема `BotAdminPermissionsChangedUpdate`, проверено 2026-10-19).

**Набор полей зависит от `update_type`.** Обязательны только `update_type` и `timestamp`; остальные поля
необязательные — API отдаёт только поля, относящиеся к конкретному типу события.

**Поля по типам событий:**

| Тип события                     | Поля                                                                                 |

## Клавиатура для чат-ботов

Клавиатуры позволяют пользователям взаимодействовать с ботами через кнопки вместо текстовых сообщений. При создании
клавиатуры соблюдайте следующие правила раскладки:

- Текст кнопки центрируется и обрезается, если он выходит за границы кнопки
- Кнопки в одном ряду всегда одинаковой ширины
- Ширина каждого ряда равна полной ширине клавиатуры
- Все кнопки имеют одинаковую высоту по умолчанию

### Inline-клавиатура

Вы можете прикрепить inline-клавиатуру к любому сообщению бота. Она поддерживает до **210 кнопок**, сгруппированных в
**30 рядов** — до **7 кнопок в ряду** (до **3** для типов кнопок `link`, `open_app`, `request_geo_location` и
`request_contact`).

### Добавление кнопок

Чтобы добавить кнопки, отправьте сообщение через `POST /messages`. В теле запроса передайте объект `attachments` с
`type: "inline_keyboard"` и массивом `payload.buttons`.

Каждая кнопка требует параметр `text`. В зависимости от типа кнопки могут потребоваться дополнительные параметры.

**JSON-пример — одна кнопка:**

```json
{
  "text": "This message has a link button",
  "attachments": [
    {
      "type": "inline_keyboard",
      "payload": {
        "buttons": [
          [
            {
              "type": "link",
              "text": "Open site",
              "url": "https://example.com"
            }
          ]
        ]
      }
    }
  ]
}
```

## Кнопка request_contact

Когда пользователь нажимает кнопку `request_contact`, он отправляет боту контакт своей учётной записи MAX и номер
телефона.

Сообщение с контактом содержит поле `hash`, которое позволяет проверить, что номер телефона совпадает с учётной записью
MAX пользователя. Это делает контакт пригодным для использования в качестве альтернативы авторизации.

### Схема верификации

1. Бот отправляет `POST /messages` с кнопкой `request_contact`
2. Пользователь видит кнопку **Share Contact** (Поделиться контактом)
3. Пользователь нажимает кнопку, отправляя боту номер телефона MAX
4. Бот получает контакт через `GET /messages`
5. Бот проверяет, что номер телефона совпадает с учётной записью MAX пользователя, сравнивая:

**Шаг 1** — получить значение `hash` из `attachments.payload`:

```json
{
  "payload": {
    "vcf_info": "string",
    "max_info": {},
    "hash": "string"
  },
  "type": "contact"
}
```

**Шаг 2** — вычислить `HMAC-SHA256(access_token, vcf_info)`, где:

- `HMAC-SHA256` — стандартная криптографическая функция, доступная в большинстве языков программирования
- `access_token` — токен доступа бота
- `vcf_info` — контактная информация в формате vCard

Если значения совпадают, пользователь поделился номером телефона, привязанным к его учётной записи MAX.

> **Важно:** перед хэшированием преобразуйте символы `\r\n` в `vcf_info` в реальные переносы строк.

> **Использование данных:** данные контакта, полученные через `request_contact`, можно использовать только для
> взаимодействия с текущим чат-ботом (например, регистрация в программе лояльности, проверка статуса заказа,
> идентификация в сервисе бота).

## Форматирование текста

Текстовые сообщения в чат-ботах можно форматировать с помощью **Markdown** или **HTML**. Укажите нужное значение в поле
`format` объекта `NewMessageBody`.

### Markdown

Установите `format` в `markdown` в `NewMessageBody`.

| Отображение                        | Markdown                                                                                                             |
|------------------------------------|----------------------------------------------------------------------------------------------------------------------|
| *курсив*                           | `*emphasized*` или `_emphasized_`                                                                                    |
| **жирный**                         | `**strong**` или `__strong__`                                                                                        |
| ~~зачёркнутый~~                    | `~~strikethrough~~`                                                                                                  |
| <u>подчёркнутый</u>                | `++underline++`                                                                                                      |
| `моноширинный`                     | `` `code` `` (переносы строк внутри трактуются как пробелы)                                                          |
| [ссылка](https://dev.max.ru/)      | `[Inline URL](https://dev.max.ru/)`                                                                                  |
| @упоминание пользователя           | `"text": "[Имя Фамилия](max://user/user_id)"` (используйте полное имя из профиля MAX; если фамилии нет — только имя) |
| <font color="red">выделение</font> | `^^highlighted^^`                                                                                                    |
| заголовок                          | `# heading`                                                                                                          |
| цитата                             | `> quote`                                                                                                            |

### HTML

Установите `format` в `html` в `NewMessageBody`.

| Отображение                        | HTML                                                                                               |
|------------------------------------|----------------------------------------------------------------------------------------------------|
| *курсив*                           | `<i>` или `<em>`                                                                                   |
| **жирный**                         | `<b>` или `<strong>`                                                                               |
| ~~зачёркнутый~~                    | `<del>` или `<s>`                                                                                  |
| <u>подчёркнутый</u>                | `<ins>` или `<u>`                                                                                  |
| `моноширинный`                     | `<pre>` или `<code>`                                                                               |
| [ссылка](https://dev.max.ru/)      | `<a href="https://dev.max.ru">Docs</a>`                                                            |
| @упоминание пользователя           | `"text": "<a href=\"max://user/user_id\">Имя Фамилия</a>"` (используйте полное имя из профиля MAX) |

## Правила комбинирования вложений

### Комбинации «Видео + изображения»

Видео и изображения можно отправлять в комбинации друг с другом и с одним вложением клавиатуры. Общее количество
вложений не должно превышать **12**.

### Комбинации с файлом

Файл можно отправлять только в комбинации с вложением клавиатуры — отправка с изображениями или видео **не
поддерживается**. К сообщению можно прикрепить только **1 файл** и **1 вложение клавиатуры**.

| Комбинация                           |
|--------------------------------------|

| 12 видео                             |

| 11 видео, 1 клавиатура               |
| 11 изображений, 1 клавиатура         |
| 6 видео, 6 изображений               |
| 1 файл, 1 клавиатура                 |

## Загрузка медиафайлов

### Как это работает

Для сообщений с медиавложениями (`image`, `video`, `audio`, `file`, `share`) сначала загрузите файл с помощью
`POST /uploads`. Ответ (`UploadEndpoint`) содержит `url` — адрес для загрузки файла (обязательное поле), а для
`video`/`audio` ещё и `token`, который затем используется в `attachments` запроса `POST /messages`. Один токен
соответствует одному медиафайлу.

Для изображений вместо токена можно использовать `url` — прямую ссылку на изображение в интернете. Для других типов
медиа это недоступно.

### Домены загрузки по типам

| Тип               | Домен загрузки        |
|-------------------|-----------------------|
| `file`            | `https://fu.oneme.ru` |
| `image`           | `https://iu.oneme.ru` |
| `video` / `audio` | `https://vu.okcdn.ru` |

### Способы загрузки

1. **Resumable-загрузка** — не multipart/form-data; можно возобновить при сбое
2. **Multipart-загрузка** — `Content-Type: multipart/form-data`; проще, но при сбое нужно начинать заново

### Обработка

После загрузки подождите некоторое время перед отправкой сообщения, чтобы избежать ошибки `attachment.not.ready`. При
повторных попытках используйте экспоненциальную задержку.

## Схемы вложений

Вложения делятся на два набора, которые различаются направлением:

| Набор               | Где встречается                                                    | Схема      |
|---------------------|--------------------------------------------------------------------|------------|
| `Attachment`        | входящие: `GET /updates`, объекты `Message` и `CommentMessage`     | 9 подтипов |
| `AttachmentRequest` | исходящие: `POST /messages`, `PUT /messages`, комментарии к постам | 9 подтипов |

Оба набора — `oneOf` с `discriminator` по полю `type`. Подтип ответа задаёт значение `type`
через `enum` из одного элемента, поэтому валидатор отбрасывает несовпадения без разбора `oneOf`.

У всех подтипов, кроме `location`, форма одинаковая: `type` + обязательный `payload`. У `location` **payload нет** —
координаты лежат на верхнем уровне объекта (официальная
`schema.yaml`, схемы `LocationAttachment` / `LocationAttachmentRequest`, проверено 2026-09-27):

```json
{
  "type": "location",
  "latitude": 55.751244,
  "longitude": 37.618423
}
```

| `type`            | Подтип ответа              | `payload` ответа                  | Подтип запроса                    | `payload` запроса                 |
|-------------------|----------------------------|-----------------------------------|-----------------------------------|-----------------------------------|
| `image`           | `PhotoAttachment`          | `PhotoAttachmentPayload`          | `PhotoAttachmentRequest`          | `PhotoAttachmentRequestPayload`   |
| `video`           | `VideoAttachment`          | `VideoAttachmentPayload`          | `VideoAttachmentRequest`          | `UploadedInfo`                    |
| `audio`           | `AudioAttachment`          | `AudioAttachmentPayload`          | `AudioAttachmentRequest`          | `UploadedInfo`                    |
| `file`            | `FileAttachment`           | `FileAttachmentPayload`           | `FileAttachmentRequest`           | `UploadedInfo`                    |
| `sticker`         | `StickerAttachment`        | `StickerAttachmentPayload`        | `StickerAttachmentRequest`        | `StickerAttachmentRequestPayload` |
| `contact`         | `ContactAttachment`        | `ContactAttachmentPayload`        | `ContactAttachmentRequest`        | `ContactAttachmentRequestPayload` |
| `inline_keyboard` | `InlineKeyboardAttachment` | `InlineKeyboardAttachmentPayload` | `InlineKeyboardAttachmentRequest` | `InlineKeyboardAttachmentPayload` |
| `share`           | `ShareAttachment`          | `ShareAttachmentPayload`          | `ShareAttachmentRequest`          | `ShareAttachmentPayload`          |
| `location`        | `LocationAttachment`       | — (координаты наверху)            | `LocationAttachmentRequest`       | — (координаты наверху)            |
