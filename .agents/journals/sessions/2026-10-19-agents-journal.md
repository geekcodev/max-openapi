## Проблема

История работы над спекой нигде не фиксировалась: после сессии оставались только коммиты, но непонятно, что именно
делалось, чем подтверждены правки и что осталось незакрытым. В `max-php-client` уже настроен каталог `.agents/`
(журнал сессий, планы, release notes) — пользователь попросил перенести этот порядок в `max-openapi`, зафиксировав
правила в `AGENTS.md`, и взять из примера всё полезное.

## Решение

- `AGENTS.md` § 6 дополнен шагом 7: после содержательных правок фиксировать сессию в `.agents/journals/` (файл
  сессии + строка в `JOURNAL.md`).
- Новый § 6.1 «Журнал сессий»: структура каталога (`journals/JOURNAL.md`, `journals/sessions/`, `plans/`),
  обязательность (каталог отслеживается в git, untracked быть не должно), формат файла сессии (frontmatter
  `tags`/`date`, секции `Проблема` / `Решение` / `Проверка` / `Нюансы`, обязательная строка о проверке с цифрами из
  последнего прогона, без секретов) и формат строки `JOURNAL.md` — колонки `Дата` · `Файл` (относительная ссылка на
  сессию) · `Теги` · `Описание` (2–5 предложений), новые сверху. Планы для задач из 3+ шагов — `.agents/plans/`,
  статус не удаляется, а закрывается.
- Новый § 6.2 «Общие правила работы» — перенесено полезное из `max-php-client/AGENTS.md`: не коммитить и не пушить
  без явного запроса (и не `git add .` наугад; различать «текст коммита» и «коммит»), полная валидация § 7 перед
  завершением с честным указанием незапущенных шагов, «если чего-то не хватает — сказать, а не упрощать молча»,
  краткие ответы и русский язык.
- § 2 (состав репозитория): добавлена строка `.agents/`.
- Создан скелет: `.agents/journals/JOURNAL.md` с шапкой и первой строкой, этот файл — он же образец формата.

## Проверка

`openapi.yaml` не менялся — из § 7 запускались только проверки, относящиеся к md-правкам: `git status --short`
(до правок дерево было чистым), просмотр diff по `AGENTS.md`. YAML-синтаксис, `$ref`, валидатор 3.1.0 и проверка
дублей ключей не запускались — спека не трогалась.

## Нюансы

- `.gitignore` содержит только `.idea`, поэтому `.agents/` попадает в git автоматически; `.gitattributes` в проекте
  нет — `export-ignore` не нужен, это не пакет для дистрибутива, а репозиторий спеки.
- `release/` из `max-php-client` здесь не заводим: у спеки нет версионирования тегами, даты релизов API ведутся в
  `DOCS_MAP.md` (регламент отслеживания `changelog-api`).
- Первый файл журнала пишется по новым же правилам — как проверка формата в деле.
